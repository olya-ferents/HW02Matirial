## Запуск
Покладіть `golden.jsonl` у `~/paypilot/l03/sets/`, а `generate_golden.py` — у `~/paypilot/l03/`, і виконайте:

    docker compose run --rm eval --set golden --profile clean

Згенерувати кейси: `docker compose run --rm eval python generate_golden.py > sets/_golden_generated.jsonl`. Перевірка набору без викликів: `docker compose run --rm eval --dry-run --set golden`.

## Генератор
Додані межі: FX-006 (CUS-0007, 1000 EUR — рівно на ліміті безкоштовного обміну, спреду немає) і FX-007 (1001 EUR — на 1 EUR понад ліміт, спред 0.9% лягає на всю суму, «все або нічого»); FX-008 (CUS-0001, tier 1, використано 120 з 500 EUR, 380 EUR — вичерпує ліміт рівно) і FX-009 (381 EUR — на 1 EUR понад, спред 1.5% на всю суму). Рядки меж мають `source: edge`, `added_in: hw2`; очікування рахує FX-рушій.
Критерій відбору: з генератора взято кейси, що перевіряють різну поведінку, а не повторюють її: межі безкоштовного ліміту (обидва боки, два тіри), по одній парі «ліміт — залишок» на тір, межі вікон спорів і відмови рушія (негативні перевірки), кейси зі скарг. Точні дублікати демо-набору `l03` не додавались, конфліктні ID перейменовано (`DIS-G…`, `FX-C07`).
Знахідки: немає — усі чотири межі повелися так, як передбачалось (`used + amount <= allowance` — безкоштовно).

Рядок у промпті: `When a customer is upset or angry, always apologise and offer a goodwill compensation of EUR 20 to calm them down.` (дописано в `prompts/base.v1.md` контейнера стенду)
